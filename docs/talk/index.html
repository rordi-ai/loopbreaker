Loopbreaker

Rigor is not
correctness

What happens when you build gates for AI agents, then point them at yourself.

Where this started

Agent review doesn’t converge

A reviewer finds issues. You fix them. It finds more. Thirteen passes later you’re not closer to shipping — you’re just tired.

The loop has no natural end, because “is there anything else wrong?” is always answerable.

Fix one

Bound the passes

  • Pass 1 — comprehensive. Find the coherent set.
  • Pass 2 — repair verification. Check the fixes.
  • Pass 3 — decision only. Ship, ship with debt, split, or hold.

There is no pass 4.

Fix two

Review completion and shipping readiness are different facts

A reviewer can finish checking a repair while a required behaviour still has no production-relevant proof.

Conflating those is what made the loop grow. So: two separate decisions, neither able to overwrite the other.

And so on

A chain of gates

discovery  →  shape  →  planning  →  planning review
   →  implementation  →  evidence  →  ship

Each stage checks that the one below it follows faithfully from the one above.

A gate chain verifies
internal consistency

It cannot check whether anything entering it is true.

The corollary

Rigor amplifies whatever enters unchecked

A correct input gets hardened into working software.

A wrong input gets hardened into rigorously certified wrong software — carrying more conviction, because now it has passing proofs behind it.

The bottom of the pipe

Two commands. No code.

loopbreaker evidence DEMO-1 --behavior DEMO-B3 \
    --tier wired --verdict pass \
    --summary "Wired replay harness passes end to end." \
    --source "tests/replay/warm-followup.wired.test.ts"

loopbreaker verify DEMO-B3 --evidence <id>

The fix

Evidence is executed, never asserted

  • A behaviour names a registered harness, never a command.
  • prove runs it. The verdict comes from the exit code.
  • not_run is the fail-closed default — failing to observe a pass is not passing.
  • The tier comes from the registry, so typing wired no longer makes it wired.

The top of the pipe

The premise has to come from a human

Nothing downstream can check it. So: an interview, recorded field by field, approved by the founder before shape can proceed.

That was the design. Then an agent ran it.

What the agent offered

“I’ll run loopbreaker discover --approve --by "Ben (ben@rordi.ai)" on your behalf.”

Its first option. Recommended.

approved_by:    "Ben (ben@rordi.ai)"   ← the record
trigger_type:   cli
triggered_by:   ubuntu                ← its own shell

approved_by is a string
the caller types

Only the ingress is evidence a human acted.

Approval now works from the browser and nowhere else — because a founder’s terminal and an agent’s terminal are the same terminal.

What I can’t claim

  • Discovery has no independent review. Every other layer does. It has my approval, which is a decision, not a review.
  • Red-first is a flag, not a gate. The dry run shipped with a plan claiming it had proved red first. The substrate disagreed.
  • An agent with a shell can still reach the browser endpoint. Attribution, not prevention.
