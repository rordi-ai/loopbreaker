loopbreaker quality control for code an AI writes

The idea

An AI can build it fast. This makes sure it's actually right.

Two things sink AI-written code: it builds the wrong thing, or it says “tests pass” when nothing ran. This closes both — a person pins down the goal up front, and every requirement is checked by a test that actually runs.

How it keeps the work honest

A handful of small pieces. Together they make sure no part of the system gets to sign off on its own work.

It plugs into the agent src/hooks.ts

  • on startreminds the agent what it's building.
  • before editsstops it jumping to code before the plan is checked.

So the process actually happens — instead of being a doc the agent ignores.

Tests that actually run

A requirement is “done” only when a real test passes — one the tool ran itself.

  • untestedcounts as failing, never as passing.
  • red firstthe test must fail before the code exists — so it can't be a fake that always passes.

You can't fake the test

  • requirementnames its test.
  • testnames the requirement back, in reviewed code.

Both halves show up in the diff, so no one can quietly attach a test that can't fail.

Reviews that end

Three rounds, then it stops.

No endless polishing — if it isn't passing after three, that's a call for a person, on the record.

Reviewed by a different AI

Review runs on Codex — a different model, over MCP.

Real independence: the reviewer never saw the code being written.

Same AI model · same starting code

The same AI, with and without the process

Both runs got the exact same one-line request and the same repo. The only difference is whether this quality process was switched on.

The request — given to both, in full “Add a way to design and send a marketing email from the dashboard.”

Without — it just runs with the one line

The AI guessed the scope and started building a full marketing-campaigns tool — saved segments, an “avg open rate” dashboard — none of it asked for (analytics was later confirmed a non-goal).

With — a short interview expands the one line first

  • Who is this for?an internal operator sending occasional announcements
  • What are we deliberately NOT doing?no scheduling, no saved segments, no open/click analytics
  • Compliance?unsubscribe + suppression list + address footer, from day one

One line becomes a scoped goal a person signed off on. That is what gets built — and what the review checks against.
